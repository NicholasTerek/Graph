# Reviewed supplier identity lab

This is a bounded synthetic example of reusable source mappings, evidence, SDK functions and native scenarios. It is not a general fuzzy matching engine. No live GitHub account was used: the example intercepts responses for a fictional repository while exercising the normal GitHub mapping path.

With FalkorDB running, run `pnpm build` followed by `pnpm demo:resolution serve`. Open the printed loopback URL and choose **Supplier identity review**. `pnpm demo:resolution verify` runs the same SDK workflow over real local HTTP using an explicitly scripted reviewer; it is not evidence of human approval or agent quality.

CSV, JSON and an issue fixture contribute three spellings of Meridian Packaging. Native relationships connect their component, product and issue evidence. Candidate scoring compares unique neighbor identities with Jaccard intersection/union, requires at least two shared neighbors and a score of 0.75, and rejects equal positive scores. The three matches score 1, 0.75 and 1. A plausible fourth supplier ties at 2/3 against both canonical candidates and cannot be selected. Scores are structural overlap, not probabilities. The function rejects more than 20 suppliers or five canonical candidates.

Select the three supported aliases, prepare a scenario and inspect the exact changes. Preparation leaves live data unchanged. Confirmation promotes the reviewed version against its live revision through the existing atomic promotion path. Three manual order references retain their IDs and move to the canonical supplier. Original aliases, source IDs and source-owned evidence remain intact; the workflow refuses to rewrite source-managed references. Replaying the three imports is a revision-preserving no-op.

A Resolution record links the contributing aliases and canonical target. Reversal prepares another reviewed scenario from the original branch diff, restores order endpoints, removes identity links and marks the audit record reverted. It refuses changed reference endpoints and stale reviews, while preserving unrelated newer properties. **Keep the original review branch:** reversal depends on its retained diff; discarding that branch removes this demonstration's reversal input. This is a limitation of the example, not a general undo service.

Observed evidence is in [the HTTP transcript](evidence/resolution-demo.json). Six native integration tests cover scoring, ambiguous rejection, explicit confirmation, concurrent promotion, runtime rollback, import replay, backup restoration, guarded reversal and dangling references. The browser suite exercises selection, review, confirmation and reversal. Fixtures, scoring and orchestration live in `examples/entity-resolution`; orchestration uses the public SDK and adds no domain-specific API route.
