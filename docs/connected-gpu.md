# A public issue in a fictional GPU plan

The optional connected-input demo replaces the bundled `gpu-142` issue with a captured public PyTorch issue, using the existing JSON source preview/apply API and source-owned native relationships. It does not change the default synthetic demo or add a domain-specific API route.

The issue was read through the GitHub connector from the public PyTorch issue endpoint. [The captured fields](../examples/semiconductor/connected-issue.json) retain the actual title, state, URL and upstream update time. The record is bound to `gpu-142` in a fictional launch. The **10-day repair duration, 20-day hypothetical duration, release/product/team binding and all supplier economics are scenario assumptions**, not facts asserted by PyTorch. The source mapping stores `fixDays: {value: 10}` explicitly; the upstream issue supplies no forecast. Closed GitHub state normalizes to the domain's resolved state before upload.

`node --import tsx scripts/connected-gpu-demo.ts verify` creates an isolated namespace, seeds the remaining synthetic records, previews one issue/two relationships, applies the source, runs the GPU calculation and checks its captured source contributor and native dependency path. Replay must preserve the revision. A branch changing the operator's repair estimate to 20 days must select the fallback driver while leaving live state unchanged. [Observed verification](evidence/connected-gpu.json) records those checks and the capture hash. `serve` opens the built UI at loopback port 3103 for inspection; stop it normally to clean its namespace.

This is a **captured public snapshot uploaded through JSON**, not a live GitHub polling connector run or authenticated provider validation. It is a real source-backed input at capture time and can become stale. To refresh, obtain current public metadata, preserve its URL identity, review state normalization and scenario bindings, then use source preview/apply again. Checkpoint/hash and upstream timestamp identify what was actually imported. Do not imply that the fictional launch belongs to PyTorch or that changing a model estimate changes the upstream issue.

The default automated video stays fully synthetic for deterministic reproduction. This separate demo proves the same reusable mapping/provenance/branch pipeline can consume a captured public engineering record. No comment or issue is sent to the upstream project.
